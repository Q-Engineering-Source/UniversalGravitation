# Bobby-Legacy scope note (2026-09-06)

**Verdict:** Bobby-Legacy may reduce *client-side visual chunk disappearance* while moving quickly through territory that this client has already received. It is not a remedy for the authoritative dedicated-server's chunk generation/loading budget, cascading worldgen warnings, or UG timeout/protocol symptoms. Those causal links remain unproven.

## What the current upstream actually is

The investigated `1.12.2` branch currently resolves to commit [`0ff8045`](https://github.com/Michael-Sebero/Bobby-Legacy/commit/0ff804559b13458ee909b24af0055ae5fa792a5f) (2026-08-18); GitHub reports no releases, so this is source evidence only, not a tested binary choice. Its Gradle metadata targets Minecraft `1.12.2`, Forge `14.23.5.2860`, Java 8, RetroFuturaGradle, and MixinBooter `8.9` ([build](https://github.com/Michael-Sebero/Bobby-Legacy/blob/1.12.2/build.gradle), [properties](https://github.com/Michael-Sebero/Bobby-Legacy/blob/1.12.2/gradle.properties)). `Bobby` is explicitly `clientSideOnly`; its core plugin loads a Mixin config ([mod](https://github.com/Michael-Sebero/Bobby-Legacy/blob/1.12.2/src/main/java/com/michaelsebero/bobby/Bobby.java), [plugin](https://github.com/Michael-Sebero/Bobby-Legacy/blob/1.12.2/src/main/java/com/michaelsebero/bobby/core/BobbyPlugin.java)). Cleanroom 1.12.2, UIE, and OptiFine compatibility has **not** been tested.

## Mechanism and cache boundary

After each client `SPacketChunkData`, it serializes the received real chunk. The client creates `.bobby/<sanitized server-or-world>/<dimension>` under its game directory, saves region (`.mca`) data there, and later supplies a read-only `FakeChunk` only when the normal client provider returns its blank chunk ([packet hook](https://github.com/Michael-Sebero/Bobby-Legacy/blob/1.12.2/src/main/java/com/michaelsebero/bobby/mixin/NetHandlerPlayClientMixin.java), [provider](https://github.com/Michael-Sebero/Bobby-Legacy/blob/1.12.2/src/main/java/com/michaelsebero/bobby/mixin/ChunkProviderClientMixin.java), [storage](https://github.com/Michael-Sebero/Bobby-Legacy/blob/1.12.2/src/main/java/com/michaelsebero/bobby/ChunkStorage.java)). Thus a “full-world cache” is possible only gradually: explore while the server supplies chunks, then retain those visited chunks locally per endpoint/dimension. The source exposes no server-world importer, generator, or prefetch protocol; an unvisited/unreceived chunk remains unavailable.

The visual outer ring is configured as `simulationDistance < distance <= renderDistance`; it is restored from local storage with asynchronous disk/deserialization work. Its own config permits 2–32 simulation chunks, 2–1816 render chunks, 1–16 chunks-per-tick, and 1–16 loading threads ([config](https://github.com/Michael-Sebero/Bobby-Legacy/blob/1.12.2/src/main/java/com/michaelsebero/bobby/BobbyConfig.java), [manager](https://github.com/Michael-Sebero/Bobby-Legacy/blob/1.12.2/src/main/java/com/michaelsebero/bobby/ChunkManager.java)). This can trade client RAM, disk I/O, CPU, and renderer/mixin risk for a larger already-known visual area; it cannot make a new remote chunk arrive sooner.

## Consequence for the current UG investigation

For high-speed movement, it is a **candidate client presentation mitigation** after cache warm-up: it could hide gaps beyond the server's sent/simulation radius and may make revisiting a route smoother. It does **not** alter dedicated-server generation, loading, collision authority, AE2 Supergiant cascading worldgen, or the server-side UG `TIMEOUT`/`PROTOCOL` path. A `FakeChunk` is deliberately inert/read-only ([FakeChunk](https://github.com/Michael-Sebero/Bobby-Legacy/blob/1.12.2/src/main/java/com/michaelsebero/bobby/FakeChunk.java)); collision and any new-area gameplay must still wait for authoritative chunks. Its included server/integrated-server mixins also enforce the configured simulation distance ([PlayerChunkMap mixin](https://github.com/Michael-Sebero/Bobby-Legacy/blob/1.12.2/src/main/java/com/michaelsebero/bobby/mixin/PlayerChunkMapMixin.java)), so the dedicated-server test configuration must not be inferred safe from the client-only annotation.

No mod/config/world/server/client action was performed for this research. **Real GPU acceptance: not executed.**

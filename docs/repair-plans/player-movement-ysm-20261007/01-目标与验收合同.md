# 01 目标、主干与验收合同

## 1. 用户原话与解释边界

本会话直接给出的现象和需求：

- “水游技艺、缩放药水也会修改碰撞箱，经过修改的玩家会无法移动，只能通过kill复位解决。”
- “行走的过程中蹲下会向前突进一点，应该也是我们的问题。”随后明确：“是实际位置前移，手感也有问题。”
- 请求参考原版行走及 `qouteall/GravityChanger`、`Gaider10/GravityChanger`。
- “以及玩家模型的六向变换、旋转也需要为其做可选适配兼容。”指定 YSM 1.12.2 release 1.1.9 JAR。
- 本轮要求方法/接口级规划与主会话目标模式入口：“本次预期为修复为止，不限时长，不代表可以无限拖延。”

合同结果是修复已报告问题及已查到的相连恢复/绑定缺陷，交付可识别产物和真实验收证据。用户要求的实际位置及手感不能以眼高平滑、相机遮掩或只看渲染截图替代。不限时长表示没有人为截止时间或自行设置的 token 预算，不表示允许无限调研、重复空转或无限扩展范围。

原修复最低完整交付如本文；不重新提出已确认范围的档位候选。2026-10-08新增F08已按用户选择明确最高档，见第7节；这不自动扩展其他项目目标。发现新的需求变更时向用户列出影响，继续不依赖该决策的工作；只有用户能缩减本合同或降低验收标准。

## 2. 授权怎样生效

本会话当前仅制作规划和提示词。由用户将 06 中的提示词发给指定主会话后，提示词明确授权该主会话恢复并实施本目录限定的修复、必要测试、NG 修复重测及交付保存。已明确的局部修复无需反复询问是否继续。

UG 主会话负责 UG 的目标、集成及最终验收。实现前重查 Git/dirty、当前写入者和运行实例，保留用户内容。跨 UIE 的最小渲染适配按 04 的文件范围和该工程约束落实 Single-Writer；同一文件不允许多个会话同时写入。该授权不把其他 UIE 功能、CHB 库升级或全项目后续里程碑自动纳入本轮。

Q-Eng 原目录用于日志/JAR/配置基线读取，不直接当作一次性测试环境。需要变更正式运行实例时，先完成候选构建、回滚包和具体替换清单，再按当时有效的用户授权执行；缺少相关授权只阻塞该正式替换链。不能从“持续修复”推导出删除原世界、全机结束 Java 或变更无关服务的必要性。

## 8. 2026-10-11 用户确认：世界位置重力的旧来源归属

既定 `WorldPositionGravity` 查询要求明确实际世界、位置和世界时间，并隔离世界持久化与实体来源。针对旧 JSON sources 和第三方 `GravityFields` 注册均没有 world/dimension 标识的迁移歧义，用户在当前 Mainline 直接回复：**“保留旧语义：无标识源明确适用于所有世界，新增可选维度筛选”**。

据此，无标识的 JSON 来源和既有第三方全局注册明确适用于所有世界；JSON 可选 `dimension` 筛选只让该来源贡献到指定维度。维度筛选不将世界持久化或实体来源变成跨世界来源：后两者仍绑定实际 `World` 对象，不能仅凭相同 dimension ID 合并。查询在该世界的同一有效世代内，叠加适用的全局来源、该世界持久化/实体来源及地板来源；合法零向量与不可用、失败分别表达，失败保留原始 cause。

本次确认沿用已授权目标、无固定死线及原验收门，不另增档位。必要自动化覆盖无标识来源在不同世界生效、可选维度筛选、同维度不同实际世界的持久化/实体隔离、叠加与抵消，以及卸载/世代变化后的查询失效。源码候选和单元结果不能替代最终候选的专服、真实客户端及用户验收。

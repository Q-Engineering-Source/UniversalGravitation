实现范围以01为合同，现有符号以02为入口。本文件给出首选责任划分及回归用例；标注“拟新增”的类型/方法尚不存在，不强制堆砌新公共接口。能够复用现有内部seam时优先复用。

## S1 将合法尺寸生命周期纳入权威状态

### S1.1 尺寸与形状的契约修正

现有`Dimensions`把原生尺寸有效性与胶囊H≥W混为一体。首选调整：

- `PlayerBodyShape.Dimensions`保存原始有限正width/height、有限非负eyeHeight，供Cardinal actual AABB使用；不把实际height改成`max(height,width)`，不向玩家字段/box注入epsilon。
- `PlayerBodyShape.FreeCapsule`及胶囊admission明确要求可表达的胶囊维度。**拟新增**内部查询`Dimensions.supportsCapsule()`可返回H≥W；`centerlineHalfLength()`仅在支持胶囊时计算，不能返回负半轴后流入CHB。
- 审计`PlayerBodyPlacement.capsule()`、`CapsulePlacementMath.pose(...)`、`BootSurfaceGeometry`和`CardinalReorientation.rotationSweepEnvelope(...)`所有消费者。进入胶囊/胶囊包络前检查支持条件并返回既有或拟新增的明确typed拒绝，不在每tick抛同一个异常。
- Cardinal移动保留真实正extent AABB，因此日志中的近等宽高数据无需伪造一个“更高”的玩家才可继续走路。真正H<W也不能仅因普通AABB有效而获准胶囊求解。
- 对H<W期间的六向reference adoption：保持当前已接纳frame可以继续移动；要改变frame时，检查现有CHB几何能力是否能用真实Cardinal box构造正确的旋转占用查询。不能套用H≥W胶囊公式。若当前有界查询暂不支持该变化，保留完整旧reference及明确pending原因，尺寸恢复后可重试；不得让普通移动永久停住、错误更改gravity或默默宣称已变向。若真实报告场景要求在此形状下完成变向且既有库不能满足，记录为相关必要依赖并协调最小CHB切片，不能以blocked跳过验收。

这里允许的是将原生正尺寸与胶囊约束分开，不是一律放松所有数学/有限性/包络校验。实施前检查已有测试对公共维度契约的依赖，并同步协议语义。

### S1.2 受控姿态变更事务

把已知姿态回调与外部几何变化的接纳统一到一个内部责任边界。建议最小接口如下，均为 **拟新增**：

```java
// 位于wi.unigrav.core.player；内部类型，优先复用ActorGeometry与Scope。
record PlayerGeometryObservation(
    PlayerPhysicalSnapshot.Scope scope, long worldTick, long revision,
    WorldCollisionCandidates.ActorGeometry geometry, double eyeHeight) {}

enum GeometryChangeSource { NATIVE_POSE, AQUA_POSE, RESIZE_EFFECT, NATIVE_CORRECTION }

sealed interface GeometryAdoptionResult {
    record Adopted(PlayerPhysicalSnapshot snapshot) implements GeometryAdoptionResult {}
    record Deferred(String reason) implements GeometryAdoptionResult {}
    record Failed(String stage, RuntimeException cause) implements GeometryAdoptionResult {}
}

// 建议放在现有PlayerPhysicsServer的内部协调方法，不强制新建Service。
GeometryAdoptionResult adoptObservedGeometry(
    EntityPlayerMP actor, PlayerGeometryObservation before,
    GeometryChangeSource source);
```

`before`必须在实际受控入口捕获。`GeometryChangeSource`只是诊断/策略输入，不是第三方mod随意宣称合法的授权token。确认相同线程、owner、scope、world/tick、expected revision、teleport fence以及mutation来源，再验证真实后的几何、锚点、占用和支撑，最后生成一个successor。未知位置跳变交给已识别的teleport/原生movement路径，不能作为“resize”接纳。

具体修改：

1. `runNativePose`从“入口失配就只运行callback并永久漏接纳”变为受控观察与结果处理。入口已失配时先分类已登记的同线程姿态变化、待ACK纠正或任意未知写入，不以宽松equals直接吞掉。
2. S0证明Aqua独立回调绕过updateSize时，在实际mod ABI的客户端/服务器对应边界安装可选hook，或在已存在的玩家更新阶段建立能验证合法非位移尺寸变化的观察。只新增经证实必要的入口，避免包裹所有实体box setter引发递归/全局副作用。
3. 缩放药水优先接其已存在尺寸API/事件；若没有事件，用S0证明的实际调用边界。不要用反射遍历字段猜“scale”。
4. `PlayerEnvironmentSampler.sample`在受控变化已提交之后重新以新snapshot观察。`Observation.matches/sameAs`保留精确上下文、位置和实际box一致性；来源不明的ACTOR_CHANGED必须继续拒绝。
5. `PlayerBodyPlacement.fromCardinalBounds`保留实际bounds和transport。非Y+frame下，原生setSize产生的世界Y直立box只是第三方候选，须围绕已接受的physical feet在frame中构建并碰撞验证，不能直接当成侧身/倒立的acceptedbox。
6. 等宽height-only潜行以实际physical feet/transport的既有契约为锚，center随height变化，切向位置不跟着center平移；eyeHeight独立更新。六向变换不围绕全局原点旋转。
7. 增宽callback若实际调用原生move，必须由单一movement路由观察、碰撞和扣同一budget。不得先认一次pose位移再commit一次；不得无证据把这次真实原生移位归零。
8. 放大后空间不足按mod/原版的占用契约拒绝或保持明确pending；保留可行的实际姿态，空间释放后自动恢复。不以穿墙、kill或无界重试解除失配。
9. callback异常保留cause；已发生的几何/位移与未发生的提交分开处理。不能无条件回滚旧位置覆盖callback产生的teleport，也不能采纳不经占用检查的后状态。

### S1.3 客户端同步与协议

现有`PlayerPhysicsClientMirror.rejection`拒绝宽度变化、高度仅白名单；须与服务端修复同一切片完成：

- `PlayerPhysicsClientSession.receive`仍先核对scope、offer、sequence、revision、nativeTeleportId、lifetime，再允许`install`。geometry变更不能成为绕过这些fence的特例。
- `rejection`校验可表示的服务器shape与当前玩家身份/存活；同一有效权威snapshot可更新mod合法宽高，不要求本地已经恰好等于它。被拒绝时给出明确原因；不是删掉所有校验。
- `install`同时投影width、height、actual AABB、transport、contacts、velocity及必要姿态/eye来源；当前只写height不足。禁止`setPosition`重建名义box丢失accepted bounds。eye来源须和实际mod/展示API一致，不覆盖独立YSM视觉scale。
- 审计`PlayerPhysicsClientSession.prepare/input`、`PlayerPhysicsClient.prepareOutgoing/applySnapshot`和`PlayerPhysicsClientPresentation.install/tick`，shape revision变化不能重复提交input或造成第二次实际位移。
- `PlayerPhysicsProtocol.getSnapshot/putSnapshot/encode/decode`保持actualbox round-trip。现有VERSION=2旧端的Dimensions构造器会拒绝H<W的新合法Cardinal状态，首选同步升级为VERSION=3并明确诊断混版本；若使用能力协商替代版本升级，必须证明旧端绝不会收到不能解码的状态。不能沿用旧版号暗中改变双端契约。协议变化与双端升级在同一候选完成。
- `NativePlayerMovement.observe`目前还要求H≥W且用名义dimensions重建canonicalbox做逐项相等。更新原生receipt的shape支持边界，保留真实before/after和box来源；不能直接把所有观察到的任意box作为receipt。

### S1.4 有意义的回归

扩展现有`PlayerBodyPlacementTest`、`PlayerPhysicsProtocolTest`、`PlayerPhysicsServerIntegrationTest`、`NativePlayerMovementIntegrationTest`、`PlayerPhysicsClientMirrorTest`、`PlayerPhysicsClientSessionTest`。建议用例名均为 **拟新增测试方法**：

- `cardinalShapeAcceptsLoggedNearEqualNativeDimensions`：实际日志三个值，actual AABB/transport不变造；FreeCapsule拒绝不支持形状。
- `nativeResizeAdoptsActualBoundsAndKeepsBudgetIdentity`：受控width+height变化后的两个真实physics tick推进；同owner/budget，无kill。
- `heightOnlySneakTransitionPreservesTangentPositionInEveryCardinalFrame`：无输入姿态变化不推进切向位置。

这些用例调用实际接纳/路由/镜像逻辑；框架fixture可构造真实几何/世界查询，但不能把“合法”判定替换为永远true。Aqua/药水真实Mixin时序仍须运行验收。

## S2 传送确认失败后的明确恢复

### S2.1 方法调整

1. `observeNativeTeleport`保持精确teleportId，清pending offer，失效travel correction fence；不创建第二owner或新budget。
2. `confirmNativeTeleport`先确认原版消费了同一ACK、owner/scope仍当前；在局部变量中完成几何验证、corrected snapshot构造和rebase方案，避免构造到一半留下半提交状态。
3. 成功路径一次提交budget anchor、snapshot、lastWorldTick、pending/native ID策略，发布正常STATE。重复ACK无新增revision或budget信用。
4. 可恢复的不支持/占用/来源问题进入明确恢复状态。首选保留custody与budget，通过现有`handleNativeDelegation/publishNative`约定把当前movement writer交回允许的原生路径，或在可接纳几何恢复后再获UG控制。不能只在finally把pending=false而保持stale snapshot继续走。
5. 意外异常在处理ACK的权威边界记录stage、scope、teleportId和原cause/stack，结束失败操作；必要的movement恢复与诊断失败分别表达。不能catch-all后发布正常STATE。状态转换的清理失败保留suppressed，不覆盖主异常。
6. `advanceOwned`对ACK失败后的明确恢复分支有实际推进/委派出口，不让`if(teleportPending)return`掩盖已消费的ACK。尚未收到真实ACK仍保持网络纠正隔离，不能用无依据的时间到期清flag。
7. `PlayerPhysicsClientSession.nativeCorrection/receiveNative`与nativeDelegated custody保持一致；旧owner writer退休后不能自动复活。respawn/dimension/disconnect清退旧状态，下一scope重新协商。

恢复状态可用现有字段表达；不足时 **拟新增** 内部`CorrectionDisposition { WAITING_ACK, ACCEPTED, RECOVERING_NATIVE, FAILED }`及cause/ID，不机械引入完整公共状态框架。

### S2.2 必须先RED的行为

扩展`PlayerPhysicsServerIntegrationTest`与`PlayerPhysicsClientSessionTest`：

- **拟新增** `confirmedTeleportWithLoggedDimensionsDoesNotStrandOwnedMotion`：通过真实确认入口消费ACK；观察后续tick的owner实际移动/明确委派，不能仅断言flag值。
- **拟新增** `failedCorrectionNeverPublishesNormalStateFromStaleGeometry`：触发责任逻辑构造/几何失败；无假成功、budget不重建，后续按恢复协议前进。
- **拟新增** `staleConfirmationCannotReanchorNewLifetime`：旧ID、旧连接、respawn和跨维度scope无效。
- **拟新增** `correctionTailFailurePreservesCauseAndCommittedPlacement`：已提交与未提交结果分别验证，不重放位移和回调。

## S3 潜行前突和原版行走手感

### S3.1 根据S0首个错误边界选择最小修改

| 首个错误边界 | 修改责任与方法 | 必须保留 |
| --- | --- | --- |
| callback结束时切向pos变化，而width未变 | `runNativePose`及实际第三方pose边界；修正feet/transport/center锚点或错误投影，不把center差写回切向pos | 原生被允许的实际增宽移动、障碍检查、eye变化 |
| pose正常，step提交两次或input重复消费 | `PlayerPhysicsStep.step`、`PlayerMovementRouter.handleOwnedPacket/assignEndpoint/finish`、`PlayerPhysicsClient.prepareOutgoing` | 单owner、单commit、同budget、原生包验证 |
| 服务器无多余delta，客户端镜像/纠正后产生真实反复端点变化 | `PlayerPhysicsClientMirror.install`、`PlayerPhysicsClientSession.receive`、nativeCorrection fence | 权威位置不靠相机平滑掩盖；服务器独立证据仍保留 |
| delta次数正常但加速度/减速/摩擦/潜行延迟有差异 | `PlayerPhysicsInput.keyboard/world`、`PlayerPhysicsStep.step`flags/friction/inputScale顺序 | 不是只复制常数，输入局部/世界转换只一次 |

当前源码在step采样之后设置sneak/sprint，再使用`.98F`和`.3F`等输入因子。先对照实际客户端输入是否已缩放及native updateSize的调用相位，再决定把flags/pose协调提前到哪个已有更新边界；不可因看到常数就断言重复缩放。

### S3.2 原版等价的范围

Y+普通地面行走，在相同重力、slipperiness、速度属性、无外力/推进配置下，对比完整顺序：

1. 当tick输入和sneak/sprint状态，原生允许的尺寸占用变化。
2. jump cooldown、onGround和支撑方块取样。
3. 摩擦`.91*slipperiness`，地面系数`AIMoveSpeed*.16277136/friction³`，空中jumpMovementFactor；`.98`与潜行`.3`仅在正确输入阶段生效一次。
4. moveRelative加速，碰撞/边缘/台阶求解，一次实际position commit。
5. 重力、drag、fall distance、方块回调及跟踪的原版顺序。

非Y+将需要的motion/支撑offset转换至已接纳local frame，世界AABB和查询留在world。已有`CardinalMovementResolver`的`.05`边缘减量不增加delta，不能通过删除edge protection“修复”前突。水/岩浆/梯子/creative flight/elytra沿用各自已有路径，至少做受影响回归，不能以普通地面公式覆盖它们。

不引入第二套vanilla travel writer。若需要共享数值计算，**拟新增**仅包内的纯方法`groundInputAcceleration(...)`或`integrateGroundDrive(...)`，输入依赖明确，结果由现有step唯一提交；没有收益则直接修正现有代码顺序。

### S3.3 回归与手感证据

扩展`CardinalMovementResolverTest`、`CardinalNativeMovementIntegrationTest`、`PlayerMovementRouterIntegrationTest`、`WalkingBodyPoseIntegrationTest`、`PlayerPhysicsInputTest`：

- **拟新增** `walkingSneakPressAndReleaseCommitOnePhysicalDelta`：同输入轨迹，有/无sneak切换，测实际delta与commit数。
- **拟新增** `groundDriveMatchesVanillaOrderingAtEqualConfiguration`：真实积分seam与固定原版基线轨迹比较；差异阈值由浮点/solver边界推导并记录，不自行给实际前突设置可忽略毫米数。
- **拟新增** `cardinalSneakEdgeClampReducesLocalTangentDelta`：六向边缘支撑offset与斜行不增量。
- **拟新增** `poseHeightChangeDoesNotSpendTranslationBudget`：真正无位移姿态改变不产生第二次movement debit；发生合法增宽移位时另测单次debit。

运行验收包含走/跑/斜行、原地及移动中潜行按松、冰等slipperiness、台阶/半砖/边缘、跳跃和碰撞，记录server pos与client镜像。用户实际试玩确认手感，不能由开发者一句“感觉正常”替代。

## S4 自动估算不绑定零尺寸helper

### S4.1 最小策略与入口

在自动estimated绑定边界建立资格判断，建议 **拟新增** `BodyPhysics.canEstimate(Entity)`或内部`GravityEntityBinder.estimatedBindingEligibility(Entity)`；优先一种，避免重复真值源。结果区分正常非物理helper与非法非有限尺寸/异常估算，后者保留可定位失败。

1. `tryBindWith`在`beginForceMutation(...).changed()`和`doBind`之前完成估算资格/结果。宽或高为0的已知helper不自动构造BodyPhysics，不更改它的noGravity或注册EntityGravitySources。
2. `BodyPhysics.estimate`保留实际已登记preset、显式质量合法性；普通正体积实体原公式不变。零尺寸但具有明确有效preset的实体按该显式契约处理，不能用全局体积过滤把它误伤。
3. `GlobalGravityTakeover.enable`可提供同一资格规则的早筛；`EntityBindingsLoader`的自动predicate仍要经binder责任边界，不能只修全局predicate而漏掉其他自动入口。
4. `refreshIfEstimated`处理正体积→零尺寸的已bound变化：撤销estimated binding和source、恢复本次绑定修改的noGravity，保留以后重新成为可估算实体时再绑定的路径。显式`bind(entity,mode,physics)`不因视觉尺寸变化被自动解除。

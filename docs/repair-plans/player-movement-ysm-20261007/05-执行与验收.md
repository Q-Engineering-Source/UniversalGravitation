# 05 持续执行、验收和交付保存

## 1. 启动目标与权威状态

用户投递06的提示词后，主会话先读README和01，再检查当前可用目标工具。当前本会话暴露的是`get_goal`、`create_goal`、`update_goal`，其运行schema优先于文档猜测：

1. `get_goal({})`检查已有目标。没有未完成目标时，`create_goal({objective: ...})`创建本轮明确修复目标；用户没有要求token预算，省略`token_budget`。不要自行设时间、轮次或预算完成门槛。
2. 已有相同兼容目标时继续该目标并按最新合同执行；已有不兼容未完成目标时如实报告工具冲突与目标身份，不能为重建本轮目标把旧目标虚标complete。受阻只影响目标注册，仍可继续本轮已授权且不冲突的必要调查/准备。
3. 只有01最终停止条件全部达成才能`update_goal({status:"complete"})`。`paused`仅在用户明确要求时使用；`blocked`按运行工具要求，在相同阻断连续至少三轮且无法继续取得实质进展时使用，不能因为困难或暂未完成就blocked。
4. 工具不支持用`update_goal`恢复目标或修改objective/budget，不编造参数或CLI命令。实际目标能力不可用时明确说明未进入目标模式，并保存恢复入口；不能用一句“已持续推进”冒充工具状态。

官方[Follow a goal](https://learn.chatgpt.com/use-cases/follow-goals)说明持续目标应有可验证停止条件和文档入口，并提供`/goal`入口；本提示词选择让主会话直接调用其实际暴露的目标工具，避免依赖特定UI的斜杠命令解析。没有必要为本轮另建定时自动化或新任务。

## 2. 执行闭环及防空转

主干顺序：S0基线/真实RED → S1尺寸接纳与双端镜像 → S2 ACK恢复 → S3实际潜行delta及原版手感 → S4自动绑定helper → S5可选YSM与远端姿态 → S6双面地板正确性/scalar冻结 → S7最高档聚合 → 最终全链验收/保存/暂存与用户实玩。S1–S3共享owner/geometry，集成由同一UG writer负责；S4可独立推进。S5纯坐标和ABI工作可以在移动方案稳定时开展，但不得抢占唯一实际客户端导致移动验收无法完成；待人工确认期间继续独立的S6/S7非人工主干。

每次切片必须形成可检验增量：新复现/排除证据、已实现行为、真实测试结果、解除一个阻塞或已保存候选。简短进展写清“当前切片、已证实什么、下一个验证点、阻塞”；不能只重复读文档和重新规划。

- 同一假设连续两次隔离实验没有新证据，改变测量点/缩小触发条件或升级独立分析，记录排除依据后继续；这是防空转规则，不是两次失败就放弃修复。
- 调研已有方法地图足够后进入RED/修复，不重新克隆所有参考库或构建通用框架。重要路线变化用机制与验收证据说明，不用工时或代码量证明进展。
- 每项失败先保留预期/实际、入口、首因和candidate身份，再修责任代码并重跑失败及相邻回归。禁止删断言、换mock-only入口或忽略已知阻断缺陷来变绿。
- 外部必需环境缺失时列出精确缺口、已尝试的有界恢复、用户需提供的具体信息/操作，继续所有不依赖它的主干。确实无可推进事项时按目标工具规则收为blocked，未完成即未交付。
- 遇到上下文压缩、进程中断、硬额度或工具故障，保留checkpoint和下一条具体动作。不限时长不保证平台无限运行；不得因此把candidate宣布OK或在后续恢复时从头重查全部证据。
- 用户已确认修复为止，不因一个切片构建通过、一次审阅结束、agent退出或日报完成而主动结束本轮目标。

实际状态继续由`docs/progress/ug-chb/推进计划.md`承载，按F/S编号写短回执和证据链接。本规划不增设另一个进度表；授权与设计需变更时修改唯一相关段并保留确认来源。

## 3. 协作与审阅

当前主会话按既有设置继续。DSH可用于所有阶段，没有按额度比例禁用/解锁规则。需要明确收益的分工时，原生worker使用GPT-6 Luna Max或GPT-6.1 Sol Low；同模块warm agent复用。独立review使用独立上下文GPT-6.1 Sol Low，读取合同、最终diff、实际测试/产物回执，而非复述实现者结论。

## 6. 保存和最终报告

保存位置沿用项目已确认交付目录；若未建立，选明确本地候选目录并在唯一账本记录。不能覆盖上一OK基线。保存包必须包含：

1. 最终UG JAR、必要UIE适配JAR及其长度/SHA-256/build ID；CHB等实际依赖manifest。
2. Git HEAD、对应diff/必要dirty源码快照，包含构建实际用到的untracked源码；不混入无关秘密或整包用户数据。
3. 构建命令、Java/Cleanroom/compile依赖来源、协议/配置开关和取用/回退说明。
4. RED/GREEN和实际运行验收回执，server/client双端哈希、GPU/实例/时间窗口、用户手感确认。
5. 已知限制与未执行项，全部验收成立前统一标CANDIDATE/CHECKPOINT；最终OK证据成立后再标OK。

commit/push/tag和正式替换按当时有效全局及项目授权执行；没有对应授权也能先在允许本地范围保存完整候选与证据，不因保存方式拖延已授权修复。最终报告写本轮档位、真实行为变化、验证了什么、未执行/受阻、产物位置和剩余动作。未完成必要运行/人工确认时不能将目标complete。

“上下面”按地板本地FACING轴的一对相反面定义，可随方块六向朝向旋转。每一面在其外侧区域产生指向该面的指向性重力：

| 地板放置轴 | 外侧位置 | 该面提供的加速度 |
| --- | --- | --- |
| ±Y | 地板上方 | 向下，指向上表面 |
| ±Y | 地板下方 | 向上，指向下表面 |
| ±X | 地板X正侧 | 向−X，指向X正侧表面 |
| ±X | 地板X负侧 | 向+X，指向X负侧表面 |
| ±Z | 地板Z正侧 | 向−Z，指向Z正侧表面 |
| ±Z | 地板Z负侧 | 向+Z，指向Z负侧表面 |

这是一块地板的两个真实相反发射面。各面的外法线为`n`时，其外侧场贡献为`−strength(distance) × n`；保持指向性平行场，距离从该实际方块面测量。两侧各自查询自己的半空间，不在同一点无条件相加一对相反向量，也不改成向方块中心的点引力。

## 2. 首选产品与兼容方案

采用**新增独立双面型**的最小方案，保留既有单面重力地板和磁性地板的ID、metadata、放置和场语义。以下名称均为**拟新增**：`FloorBlocks.DOUBLE_SIDED_GRAVITY_FLOOR`、注册ID `unigrav:double_sided_gravity_floor`、中文名“双面重力地板”。执行者可在既有命名规范下调整名称，但须记录最终ID和取用路径。

双面型共用一份profile，两面强度相同；每面独立沿用既有地板的范围和衰减。当前源码`FloorWorldFields.BUILT_IN_PROFILE`为`FloorFieldProfile(32.0, 8.0, 16.0)`，即每面近段1G、0–8m均匀，8–16m衰减，16m及以外为零。每面覆盖其外侧`1×1×16m`柱域，不把16m对半分，也不自动把单面强度翻倍。最终若当前候选采用不同已批准profile，双面型复用该profile并在回执中注明。

场贡献继续与世界、区块、区域、其他地板及有效磁力按向量相加。验收单块方向时先使用可控的无其他场环境；存在世界向下1G时，上侧向下1G可合成向下2G，下侧向上1G可被抵消，不把抵消误判成双面地板失效。

同一块地板两面各有正确的standing face证据：在上侧可正常站立，在下侧可倒立行走；六向朝向推广到墙面两侧。实际接触、`onGround`、玩家物理reference和合力保持原合同的分离；不会因为存在双面块就强行附着、穿过实体地板或关闭G。

本追加不要求双面磁性地板、两面不同挡位、红石控制、通用多面方块或整套JSON重新设计。若当前已存在地板配置入口，增加该类型必要的mode/profile接入及旧配置回归；若尚未实现，不为此重启全部未来配置里程碑。

## 4. S6实施顺序与拟新增内部接口

1. **先建立两条真实RED。** 使用实际`ExtendedBlockStorage`放置拟双面block状态，验证扫描生成正反两源；通过真实`FloorFieldIndex.replaceChunk`提交同坐标相反face，记录当前重复位置拒绝。测试直接调用现有发现/索引逻辑，不用源码contains证明双面行为。
2. **注册与面选择。** 在`DirectionalFloorBlock.Kind`增加拟`DOUBLE_SIDED_GRAVITY`，增加拟方法`List<EnumFacing> emissionFaces(IBlockState state)`：旧类型返回`[facing]`，双面型返回`[facing, facing.getOpposite()]`。方法也可放在同包解析器，但应只有一个面策略来源。发射源的field Kind仍为`FloorFieldIndex.Kind.GRAVITY`，不误归MAGNETIC。
3. **一格多源发现。** 将`sourceAt(...) -> Source`接缝改为拟`List<Source> sourcesAt(int x,int y,int z,IBlockState state)`，一格保存不可变源列表；`update/reread`一次替换或删除整对。`snapshot`展平并按坐标、face确定性排序，不能用Position map的第二次put覆盖第一面。源坐标保持真实方块坐标，不将反面假放到相邻空气格。
4. **按发射面去重。** `FloorFieldIndex.validateBatch`首选拟`EmitterKey(x,y,z,face)`代替仅`BlockKey(x,y,z)`：同坐标相反face允许；同坐标同face重复仍拒绝，包含kind/profile不同的冲突也在改动旧索引前拒绝。六个face-specific列已分别存储；先核对`addIndexed`实际键语义，不删除其唯一性不变量。整个batch验证后原子替换，同一source不重复累计range或strength。
5. **生命周期和数量门。** 放置、破坏、旋转、方块替换、chunk卸载/重载、世界重进必须同时增删两面。旧generation卸载不得删除新generation任何一面；一次读取/发布失败不留下半对或伪造零场。诊断中的physical block数与emitter数分开，两面算两个emitter但每侧各贡献一次；限额保留有界语义。
6. **玩家与邻接集成。** 验证`sampleForStanding`对应两侧外法线、`Evidence.withFloorSample`及单owner玩家的真实六向运动。`BootWorldSurfaces.profile`补已知新块资格，真实碰撞仍只是一块固体。已有靴子或磁性判断保持其自身配置，新增重力型不自动成为磁力源。
7. **取用与绘制。** 补`FloorBlockModels.registerModels`、`assets/unigrav/blockstates/`、`models/block/`、`models/item/`和中英本地化的新增资源；两相反面能被识别，旋转后仍正确。可以复用现有纹理/模型资产，需正确的双面标识和取用路径，不引入无关视觉重做。
8. **验证、候选和接纳。** RED→GREEN、相邻回归及完整发布gate后，按下述专服/真实GPU场景验收；由Mainline Owner更新唯一推进账本和交付manifest，绑定同一最终产物。F07未完成时原修复切片仍可保存其真实checkpoint，但本轮最终目标不能complete。

## 5. 必需验收与测试落点

现有测试类：`DirectionalFloorBlockTest`、`FloorChunkSourcesTest`、`FloorFieldEmitterTest`、`FloorFieldIndexTest`、`FloorWorldFieldsLifecycleTest`、`FloorDebugSnapshotTest`、`BootWorldSurfacesTest`、`FloorStandingEvidenceTest`、`StandingConstraintsTest`。必要时在现有真实MP/世界fixture内补玩家集成。以下方法名均为**拟新增测试**：

- `doubleSidedFloorEmitsTowardBothOppositeFacesInEveryOrientation`：六种FACING，每个外侧点朝地板；地板固体内部、柱域侧外和范围外无该面额外场。
- `storageScanAndRereadPublishOppositeFacePairAtomically`：真实初扫、旋转、移除、替换和snapshot不可变；旧单面只一源。
- `indexAcceptsOppositeFacesButRejectsSameFaceDuplicatesBeforeMutation`：相反面接纳，重复同面拒绝且既有索引不损坏；每侧强度不翻倍。
- `chunkGenerationRemovalClearsBothEmittersWithoutErasingReplacement`：卸载两源，旧owner不能误删新对。
- `doubleSidedFloorPreservesOppositeStandingReferencesAndVectorComposition`：两侧standing/reference与实际合力分别验证，世界/区块场叠加、抵消及相邻块半开边界无重复计账。
- `builtInDoubleSidedFloorRemainsSupportedByBootCollector`：新增block实际碰撞callback入口可用，无新UNSUPPORTED，无新增假磁力。

## 3. 选定表示：每个section片页的平面覆盖，保留物理源语义

新增包内纯Java类型`src/main/java/wi/unigrav/core/floor/FloorChunkCoverage.java`，不导入Minecraft。它同时作为压缩scanner已提交缓存和index查询视图；索引不再编译第二份逐格对象。最小不可变结构：

```java
final class FloorChunkCoverage {
    record Mask256(long w0, long w1, long w2, long w3) { }
    record PlaneGroup(Kind kind, FloorFieldProfile profile, Mask256 cells) { }
    // SectionCoverage内部按Face、localNormal(0..15)保存组；不暴露可写数组。
    // chunk顶层按sectionY存SectionCoverage；生产最多16个section。
    static final class SectionCoverage {
        List<PlaneGroup> groups(Face face, int localNormal); // 预建不可变视图
        int normalPresence(Face face);                     // 低16位
    }
    SectionCoverage section(int sectionY);                 // absent返回null
    record Stats(long physicalBlockCount, long emitterCount, long groupCount,
                 long nonemptySectionCount, long maskPayloadBytes) { }
}
```

顶层使用稀疏sectionY目录；生产dirty复制最多16个section引用，并只复制受影响face/normal bucket及其group/mask。兼容`replaceChunk(List<Source>)`原本接受任意int Y，不新增0..255限制，也不为极端稀疏Y分配巨型连续数组。世界scanner继续只读实际0..255存储。每group固定4个long即256格覆盖，不构建无限世界平面或用一张巨型世界bitmap。

| 面 | 法向块坐标n | 切向片页坐标 `(pageA,pageB)` | 片页内bit，`a + 16*b` |
| --- | --- | --- | --- |
| DOWN／UP | y | `(floorDiv(x,16),floorDiv(z,16))` | `(floorMod(x,16),floorMod(z,16))` |
| NORTH／SOUTH | z | `(floorDiv(x,16),floorDiv(y,16))` | `(floorMod(x,16),floorMod(y,16))` |
| WEST／EAST | x | `(floorDiv(y,16),floorDiv(z,16))` | `(floorMod(y,16),floorMod(z,16))` |

group身份为同一chunk/section、face、n、Kind及**三个profile double的精确位值**；不得量化、取平均或按相似profile合并。以`Double.doubleToLongBits`比较，保留合法signed-zero区别。相同平面不同kind/profile允许覆盖不同格；所有group在同一face/n上的mask必须互斥。相同格相同face再次出现，哪怕kind/profile不同，也要在改变任何旧状态前拒绝。相反face可同格并存，双面块两面按同一delta发布。

一个覆盖了256格的group，在某个查询点最多命中其所在**一个格**；贡献仍是该格的原强度，**不乘面积，不做面积平均**。不同法向平面的范围重叠则逐个相加；不能把多层地板折成一个平面。`physicalBlockCount`按xyz的并集计数；`emitterCount`按xyz/face计数，双面块贡献1个物理块、2个发射面；`groupCount`仅是压缩结构数。三个数不得互换。

拟新增核心方法：`FloorChunkCoverage.compile(ChunkKey,List<Source>)`用于公有兼容整批入口，完整验证后构造；顶层`section(int sectionY)`先取得明确高度片页，再调用`SectionCoverage.groups(Face,int localNormal)`，返回在prepare时预建的不可变List视图，getter不分配且不暴露可写PlaneGroup数组。X/Z面须使用RoutedShard记录的sectionY，法向localNormal为floorMod(x或z,16)；UP/DOWN为floorMod(y,16)。不能只给Face/normal就在多个高度section之间任选bucket；只读group遍历可按List下标避免临时iterator。`hasEmitterAt(int x,int y,int z,Face)`／`matchesCell(int x,int y,int z,int descriptor,FloorFieldProfile profile)`用于dirty旧值查询。短命包内`CoverageEdit.replaceCell(int x,int y,int z,int descriptor,FloorFieldProfile profile)`只复制触及bucket，`finish()`产生CoverageDelta；它由scanner私有`applyStoredCell`调用，不引入可抛用户reader callback或通用服务接口。`appendDebugSources(Vec3,int,List<Source>)`仅有界调试展开；`stats()`遍历真实结构返回计数，测量区间外使用。

## 4. 接口、所有权及稀疏查询

保留`FloorFieldIndex.Source`六字段、`Kind.GRAVITY/MAGNETIC`、`ChunkKey`、`replaceChunk(ChunkKey,Object,List<Source>)`、`removeChunk(ChunkKey,Object)`、`clear()`、`sample(Vec3,double)`、`sampleForStanding(Vec3,double)`签名和异常/有限数契约。`Source`文档改称“一发射面”，公有整批替换仍允许全量验证/编译；它不是生产dirty路径。`Sample`、`StandingSample`及standing消费者不变，避免新增协议/配置。

在`FloorFieldIndex`内新增包内类型及方法（不是公共API）：

```java
record PageKey(int a, int b) { }
record PublishedChunk(Object owner, long revision, FloorChunkCoverage coverage) { }
static final class ChunkView { /* 只有一个PublishedChunk current指针 */ }
record RoutedShard(ChunkView view, Face face, int sectionY) { }
static final class PreparedPublication { /* base、next、route/range补丁、undo */ }
PreparedPublication prepareReplacement(ChunkKey key, Object owner, FloorChunkCoverage next);
PreparedPublication prepareDelta(ChunkKey key, Object owner, CoverageDelta delta);
PreparedPublication prepareRemoval(ChunkKey key, Object owner); // stale owner返回null
boolean isCurrent(PreparedPublication publication);
ChunkView commitPrepared(PreparedPublication publication);
void close(); // 包内生命周期终止；public clear仍可复用
```

`CoverageDelta`由scanner准备，含`baseCoverage`精确对象、`nextCoverage`、受影响section/face/normal标识、old/new真实源数及range计数变化。它不含整chunk展开的Source列表；unchanged返回`NoChange.INSTANCE`，不制造假空delta。revision只在有效覆盖发布后加一，使用checked递增；NoChange不变。`prepareDelta`对owner用`==`，base覆盖对象/revision精确核对，禁止用owner.equals或只用chunk坐标。

`prepareReplacement`捕获当前base并允许现有公有replace契约更换owner；WorldFields仍先确认新ChunkState确为当前代。**ChunkView只在同owner、同generation的局部delta或同代替换中复用**；owner身份变化，或unload/reload、WorldFields重新load产生新generation时，必须创建新ChunkView，不能按chunk坐标复用旧view。index的current view精确身份也是generation token；prepared记录`expectedView`、baseCoverage、owner/revision，WorldFields另核精确ChunkState对象。旧view在成功换代、卸载或close后current失效，旧scanner附件明确不可用，永远不能跟随新generation coverage。每次prepared一次性；已提交、旧view失效、current view identity或revision变化均拒绝。`CoverageDelta`作为包内record实现Refresh；mask/group数组私有，不向调用者暴露可写引用。

`isCurrent(prepared)`必须同时满足`!closed && !invalid && !prepared.consumed`、`chunks.get(prepared.key) == prepared.expectedView`（delta/removal为确切非null旧view）、expectedOwner身份、baseCoverage对象及revision相同。换owner replacement的expectedOwner来自旧base，nextOwner来自新调用，两者不能混作一个校验字段。**目录成员身份栅栏必需**：unload/clear后即使旧view仍被scanner/prepared引用、旧current暂未改，也不能重新登记它的路由。prepare另捕获index的clear epoch；clear在清空目录前改变epoch并使旧view失效，避免初次replacement的expectedView为null时在clear前后以null==null复活。public clear仍保持可清空后复用，包内close不可再prepare/commit。新owner replacement保存expected old view与candidate new view两个角色，不用new view取代提交前的成员校验。

六个face的路由目录改为`Map<PageKey,NavigableMap<Integer,RoutedShard>>`，TreeMap键是**法向16格slice**，而非每格切向column或逐面源。UP/DOWN的slice是sectionY；X面是chunkX；Z面是chunkZ。每shard只能属于一个具体chunk generation，读其ChunkView当前coverage的指定section/face。同chunk同代的所有shard指向同一个view；换代预建new-view route patches，旧route/value预存用于回滚，成功后旧view失效。group/mask对象由扫描缓存和索引共享。

查询顺序：有限point转切向整数（沿用越int边界无命中规则）→floorDiv/floorMod确定唯一片页及bit→按原`boundedEntries`范围得到法向块坐标上下界→floorDiv得到稀疏slice区间→TreeMap有界遍历→slice内n升序→只在bit命中的group取贡献。Face顺序保持`DOWN,UP,NORTH,SOUTH,WEST,EAST`；同face按n升序保持scalar浮点累加顺序。不可遍历全世界/全chunk，不可按巨大的range逐个扫描空chunk。最后仍精确检查`[0,range)`及切向半开边界，粗筛不可改变有效范围。

slice内允许在不可变SectionCoverage保存每face的16bit normal presence（可用int低16位），只枚举非空normal bucket：先限制query上下界，再反复`Integer.numberOfTrailingZeros(bits)`及`bits &= bits - 1`，仍为n升序，避免无条件访问16个空桶。presence与group在同一coverage提交，不是可独立陈旧的可变cache；这是表示/循环细节，不新增公共接口。先证明标量order等价，再用多profile/多层真实sample测量；优化不能令这些常用场景明显退化。

range登记按真实发射面计数（long checked）；group保存profile range，delta仅调整受影响range键，最大range只在发布完成后更新。正常路径不重建整个range TreeMap。strength、plateau、range公式沿用`FloorFieldProfile.strengthAt`，在转double后才算n+1，避免int MAX溢出。sample需要的向量可用轴分量累加减少临时Vec3，但每次加法/磁响应乘法继续检查finite；保持零值、有效face及磁乘法下溢的现有语义。不得额外使用并行reduce、FMA、排序或代数重排。

## 5. Scanner：首扫、局部读取与真正NoChange

修改`FloorChunkSources.java`，删除常驻`Map<Position,List<Source>>`及逐格Source对象（这是冻结后要替换的scalar结构）。保留`scanExisting(int,int,Supplier<ExtendedBlockStorage[]>,FloorFieldProfile)`工厂和存储合法性验证。首扫仍检查当前16-section数组及section YLocation，逐非空section读取真实`ExtendedBlockStorage.get`，在短命group mask builder中按整数descriptor汇集，完成后冻结coverage。既有`snapshot()`和`reread(int,int,int)`如测试/内部旧入口需要可保留为包内兼容路径，但**WorldFields增量流程不得调用snapshot或逐格兼容commit**。

若保留reread，只允许尚未attach的独立scanner更新其initialCoverage供现有存储测试；已绑定生产view的scanner不允许该入口独自改cache，应明确拒绝并由WorldFields走prepare/commit。snapshot读取当前committedCoverage并展开，保留兼容/调试用途，不进入生产刷新和计时内的压缩路径。

拟新增方法：

```java
FloorChunkCoverage initialCoverage();
FloorChunkCoverage committedCoverage();
long committedRevision();                 // candidate-only只读观察，不进公共API
Refresh prepareReread(DirtyBatch dirty);    // 只构造，不改已提交缓存
void validateAttachment(FloorFieldIndex.ChunkView view);
void attachPublishedView(FloorFieldIndex.ChunkView view); // 校验已提前完成，只有字段赋值
sealed interface Refresh permits NoChange, CoverageDelta { }
enum NoChange implements Refresh { INSTANCE }
```

`FloorChunkSources`首次发布前只持未发布initialCoverage，发布后attach到该generation的ChunkView；其`committedCoverage()`以后**总是读取该view.current.coverage**，不再有第二个独立可变cache指针。绑定永久限定该view identity；新generation创建新scanner附件和新view，旧view invalid后明确拒绝读取，不能返回ZERO、初始coverage或新世代结果。`CoverageDelta`和上述Refresh可作为`FloorChunkCoverage`的包内nested types，避免为数据声明增建一批文件。所谓cache commit，就是index切换共享PublishedChunk的一次线性化；不存在“先发布index，再调用可抛异常的cache更新”窗口。初次attach和`ChunkState.sources/reader`清理只在已经预验证之后做字段赋值。

`descriptorAt(IBlockState)`优先返回primitive int：非源0，单面重力六码、单面磁六码、双面重力三轴码。双面PRIMARY与opposite交换但有效两面/profile一致时可NoChange；视觉/方块state仍由Minecraft正常更新。新descriptor与当前该格有效faces/kind/profile精确一致才NoChange；不能比较IBlockState对象引用或只比较是否是地板。builtin profile当前固定；将来已有真实profile修改入口必须明确invalidate对应owner/cache，本轮不为未来配置系统造架构。

`prepareReread`每个dirty格最多读一次当前真实state；storage supplier一次获取当前数组（包括替换数组），不缓存陈旧section引用，不调用World.getChunk来加载/生成。只在第一个有效差异出现后创建局部builder；去掉旧格所有发射面，再插入新格完整发射面，单批结束后冻结受影响bucket。同格多次dirty合并，读取最终stored state；气体/普通方块替换及无效请求结果均以真实存储为准。

`DirtyBatch`在`FloorWorldFields`内使用按`y*256 + localZ*16 + localX`编码的位集（每chunk最多65,536bit），两个可复用bank支撑detach及重入dirty；不要常驻Position/HashSet节点。无dirty的chunk不必预分配两bank。位集迭代只产出primitive编码；首次scan期间发生的mark进入另一bank，下一次有界flush继续处理，不循环直到空导致无界重入。

## 6. WorldFields发布事务与失败责任

修改`FloorWorldFields.WorldFields.flush(boolean)`及`ChunkState`；新增私有`refreshChunk(ChunkKey,ChunkState,DirtyBatch)`、`commitRefresh(…PreparedPublication…)`、`isCurrentState(ChunkKey,ChunkState)`、`restoreDirty(ChunkState,DirtyBatch)`。外层公共方法签名、服务器世界线程校验、snapshot/restore延期、Optional不可用语义不变。

严格顺序：

1. `closed || deferred || pending.isEmpty()`立即return；**空pending不构造work Map、dirty副本、Source snapshot或编译**。采样仍查询已提交index。
2. detach一次pending/dirty批次，记录确切ChunkState对象、owner、baseCoverage/revision；新mark进入另一个bank。仅对现有同世代state准备。
3. 首次reader.get/scan或局部prepareReread；允许真实supplier在此重入mark/load/unload/close。失败时旧提交缓存与index不变，保留/合并dirty、pending和原cause；首扫失败保留reader以便重试。
4. 重查closed、`chunks.get(key) == state`、`state.owner == owner`及base/revision；旧世代准备结果直接丢弃，**不把它的dirty合入新世代**。NoChange只清掉这一detach批已处理的dirty；有新mark则继续pending，不publish、不递增revision、不编译/全snapshot。
5. 有变化时`index.prepareDelta`（首扫prepareReplacement）生成候选、路由/range补丁及预先分配的undo记录；完成重复、mask互斥、计数/finite、owner/base校验及初次cache attach预验证。此时不得修改已提交coverage。
6. `commitPrepared`进入无回调、不可重入的世界线程临界段。prepare已构造`RoutePatch[]`、`RangePatch[]`及全部undo数组，预存旧key/value、boxed新计数、删除键和新/旧view。前段只新增节点或覆盖**仍存在的旧entry**；拟删除的旧route/range key保留至线性化后，不先remove再靠put重建。所有可能分配/失败的容器插入在**线性化之前**；每个修改点在发生前已有undo项。失败用预存键/旧value覆盖尚在的旧节点、移除刚插入节点，无节点重建/装箱/日志/临时collections。若map插入失败后无法证明旧结构已恢复，明确invalid并propagate原cause/suppressed，不能宣称旧index仍可用。
7. 在改chunk目录入口前再核对prepared base/current-view identity；首次缺entry时，最后一项预线性化插入创建预建new-view的目录node，仍受undo保护。既有entry保持至此、换代仅在最终无可抛段覆盖其value；不要先改目录再用expected-old-view检查自身编辑而误判stale。世界线程临界段没有外部callback/重入，所以最终校验与激活之间不会发生其他世代变化。同代一次`view.current = nextPublishedChunk`同时发布两面、索引查询数据及scanner缓存视图；换代的new-view激活、已有chunk入口切到new view、old-view失效及scanner安装在同一无可抛/无回调提交段内完成，禁止期间sample/reentry，旧附件不会看到new coverage。线性化后只用预存数组按下标做引用/primitive赋值和按已有键移除无效节点；**不临时构造iterator、key、日志、collections或boxed计数**，不增长容器、不运算profile或重编译cache。maxRange用已准备值赋值。首次state.sources安装/attach同样无可抛校验。
8. 已处理dirty bank清理/归还复用；新dirty仍pending。`prepareSample`在pending残留/closed/deferred时返回Optional.empty；存储/发布异常明确向上抛，不包装为zero field或旧值成功。保留上一已提交index是重试/诊断基线，不授权向玩家把stale结果当新成功。

`commitPrepared`必须封住正常错误发生在切换后的路径；公开sample、remove/replace不能在其执行中重入。纯index调用者仍承担同owner线程契约，不借此新增并发采样支持。undo故障不能吞掉：保留主异常和suppressed，标记受影响index不可采样并明确失败；不可继续返回部分场。VM不可恢复错误不能承诺可靠复原；普通存储/校验/准备/插入失败的**旧状态+dirty保留**必须行为测试验证。

`removeChunk`保持精确owner拒绝旧unload，通过prepareRemoval/commitPrepared同一事务路径删除当前view拥有的所有shard/range。removal线性化为view.current失效，已绑定scanner不能把失效view解释成有效空cache；解除supplier/cache引用由WorldFields随后无可抛地完成。unload先完成index removal，再按既有键移除ChunkState/pending；如准备失败，保留精确state及卸载意图并抛原cause，后续仅重试removal、不重读已卸载存储、不把stale index返回为成功。此状态用ChunkState内具体`unloadRequested`标志即可，不另造通用生命周期框架。新load先预分配新state、完成旧owner失效后安装新state，scan仍走现有pending；旧prepared与unload不得命中新owner。

unload→reload产生新owner；clear/close使view失效并释放scanner supplier、dirty banks、view路由和计数，不留下已卸载Chunk/World的长期引用。WorldFields.close调用index包内close，终止状态与public clear的可复用语义分开。首次load依旧全扫；重入/失败保留bounded retry，不每次玩家移动重新全扫。拟增`FloorWorldFieldsLifecycleTest.failedUnloadKeepsRemovalIntentWithoutRereadingUnloadedStorage`验证上述真实生命周期入口，不能只测独立index删除。

## 8. 自动性能runner：真实baseline、全刷新入口、分开解释指标

拟新增common driver `src/perf/java/wi/unigrav/core/floor/FloorAggregationPerfRunner.java`（同包仅为访问真实包内WorldFields seam）、candidate-only helper `src/perfCandidate/java/wi/unigrav/core/floor/FloorAggregationDiagnosticsRunner.java`、`gradle/scripts/floor-aggregation-perf.gradle`及任务`floorAggregationPerf`。build.gradle仅引入该脚本，perf sources/dependencies不得进入发布JAR；复用现有Java25及mapped Minecraft/test bootstrap，不引入第三方benchmark框架或改JDK target。配置参数只用于runner：`-PfloorPerfBaselineDir=…`、`-PfloorPerfOutput=…`、`-PfloorPerfMode=compare`；这些任务/参数**当前不存在**。

runner具体方法：`main(String[])`、`runComparison(Options)`、`runChild(Variant,FixtureId)`、`createFixture(FixtureSpec)`、`verifyEquivalentTrace(ScalarTrace,CandidateTrace)`、`measure(Operation,int,int)`、`consume(Sample)`、`consume(StandingSample)`、`writeReport(Path,Report)`。用真实`WorldFields.load/markDirty/flush/sampleForStanding/unload`及真实ExtendedBlockStorage，不造简化flush或替代index。每child跑该fixture的全部operations，操作间重建/恢复状态，避免为每个operation启动数百个JVM。baseline child加载冻结scalar compiled inputs和同一runner；candidate child加载当前candidate。common runner只调用两版本保留的共同入口，候选结构诊断单独编译为perf helper，不给scalar源码添加新结构API。父进程检查两份classpath身份，禁止当前main classes意外遮蔽baseline；实际被加载类来源和SHA进入报告。

**选定链接协议与编译任务**：脚本声明`floorPerfCommon`（src/perf/java）和`floorPerfCandidate`（src/perfCandidate/java）两个独立source set。`compileFloorPerfCommonJava`的classpath为冻结baseline compiled-classes、其UIE API10 compile输入及锁定的mapped Minecraft/外部依赖，**不包含当前main output或candidate helper**；共同driver只编译一次，以基线可用API为上限。`compileFloorPerfCandidateJava`只对common output、当前main output及同份外部依赖编译。common parent需要floor类型时使用baseline CP；`floorAggregationPerf`在两个compile task及candidate classes准备后调度独立child，不用含两版本的混合CP。

baseline child CP=`common output + frozen compiled-classes + frozen UIE API10 + pinned external dependencies/resources`；candidate child CP=`common output + current main output/resources +相同冻结UIE API10 +同份pinned外部依赖`；candidate诊断child额外加入`floorPerfCandidate output`并执行`FloorAggregationDiagnosticsRunner.main`。baseline CP绝不加入candidate main或诊断helper，candidate CP绝不加入frozen floor compiled-classes。冻结metadata用于恢复/核对依赖列表，缺失则明确LINKAGE/ENVIRONMENT BLOCKED，不能直接借当前main runtimeClasspath覆盖旧输入。两版本floor类必须由各自CP实际加载，记录代码来源与inventory身份。

## 9. 收口标准、执行顺序及交付

## 11. S7d 查询路由页实现补充

本节是已批准的 S7d 方法级实现补充，优先于第 10 节中旧的 S7a 下一步描述。它只针对已冻结 mask 源码的查询路径，不改变 R114 scalar、coverage、profile/mask、published ChunkView、owner、range 或发布语义。当前 JFR 已定位 TreeMap slice seek 为实际热点；本补充规定实现形状，但性能收益仍须由同一固定 baseline、同一外部 classpath、同一查询 schedule 的窄测量证明。

Index 内的 routes 改为 EnumMap<Face, Map<PageKey, RoutePage>>。私有不可变 RoutePage 保存严格升序且无 null 的 int[] normals 与等长 RoutedShard[] shards，并提供 lowerBound(int)、normalAt(int)、shardAt(int)、shardAtNormal(int)。sample 对每个实际访问的法向页只二分一次，再按数组 ordinal 升序扫描到 upper；不保留并行 TreeMap、重复查询 cache 或性能 fallback。registeredRanges 继续使用 TreeMap。保留当前 sliceBase/range mask、normal 递增顺序、profile/mask 求值、StandingSample、相同 publication、owner/current 与全局 range fence，以及合法单 normal hole 和多 normal 摘要指向缺失 shard 时的异常语义。

prepareRoutePagePatches(RoutePatch[]) 按 face 与 PageKey 分组，捕获每页 expected identity，并在发布前构造 staged/final RoutePage、逆序恢复信息、attempt 标志和 logical normal hook ordinal。未变化页复用原对象；没有 route patch 的 profile/mask 局部修改不得复制 RoutePage。多项逻辑 normal addition 即使共用一次整页 staging，也仍按原顺序逐项执行对应 hook 和身份核对。

事务提交必须先验证目标页仍为 expected，再 stage；stage hooks 后及线性化前重新核对所有 expected/staged page 身份、chunk owner/base/current、clear/range epoch、consumed/invalid 状态。CHUNK_DIRECTORY_INSERTED hook 位于 ChunkView.current 指针发布之前；校验需要识别本事务已尝试插入的目标目录项，同时继续验证 owner/base 与 epoch。现有 ChunkView.current 仍是线性化点。之后只能用预分配的 PageKey/数组更新已存在 route map value 或删除旧 key；禁止新建 map 节点、clone/with、boxing、集合/iterator、回调、日志或 profile 数学。

发布失败时仅按逆序撤销由本事务 identity 安装的 staged page；仅当当前仍是 expected 时允许 no-op，其他 foreign identity 绝不覆盖。若目录/page undo 不能证明完整恢复，应将 index 标为 invalid，并以原始异常 cause/stack 失败；undo 异常以 suppressed 关联。attempt 标志必须在可能部分成功的 map put 之前设置，精确重试仍按现有契约验证。验证分出多 normal 同页添加/替换/移除且保留其他 normal、同页 A prepare 后 B 发布非重叠编辑则 A stale 且不覆盖 B、不同页同 range 不互相 stale、同页重入及 foreign undo 失败 cause/suppressed/invalid、partial route/range/directory stage exact retry；并保留六向、孔洞、mixed profile、极值、standing、overflow 及原 95 项 focused coverage。

typed retainedCounts 只报告实际 route page 数组与其 primitive payload/reference slots，和现有 mask、group、emitter 等字段分开命名；这些是结构与 payload 统计，不宣称总 heap。route page 局部重建/数组复制成本必须由窄测量体现。执行顺序为 API10 受影响 focused tests、独立稳定源码审阅、mixed_six_face/double_six_face/public_mixed_profiles 三 fixture 三 fork 的固定输入窄测；只有窄测通过才评估完整九 fixture gate，未通过时保留原 NG 并继续诊断，不降性能门槛、不运行发布 gate。

## 12. Matched-cell scalar and canonical face-set candidate

Matched-cell scalar sampling computes a signed normal component only after the existing page/bit/group hit and range checks. `strengthAtMatchedCell(face, normal, coordinate, profile)` preserves each face's original signed expression; gravity and magnetic x/y/z components are checked and accumulated in the original contribution order. Magnetic response multiplication and addition remain per-component, including zero multiplication, so signed-zero and floating-point ordering semantics stay observable. Magnetic face membership is decided from the unscaled contribution and positive response, preserving underflow behavior. Empty face masks reuse `Vec3.ZERO`; nonempty masks construct the result vectors. The public `Sample` constructor continues to validate and defensively copy external sets.

The next single optimization candidate replaces per-sample gravity and magnetic `EnumSet` accumulation with private six-bit integer masks, then maps each mask to one of 64 privately constructed immutable `CanonicalFaceSet` instances. The cold table is global/shared, not retained per index. Only the private marker type may bypass `Sample.immutableFaceCopy`; all caller-supplied sets retain the existing null, element, validation, and defensive-copy behavior. The marker delegates the complete read-only `Set` surface and explicitly rejects every mutator, including no-op mutation attempts. Candidate diagnostics report the global table and its delegate structures separately from per-index retained counts; these counts describe global shared structures and do not claim total heap bytes. This candidate remains unaccepted until its focused behavior tests, typed diagnostics, complete input binding, and fixed-input narrow comparison pass. The matched-cell candidate's three-fixture narrow run remains a performance NG: mixed/double/public `sample_index` p50 ratios are all above the current gate; allocation and dirty-update gains do not offset that regression. No threshold is lowered and no full nine-fixture or release gate is inferred from the correctness tests.
## 13. RoutePage compact presence-rank candidate

当前 canonical face-set query JFR 只作定位证据：目标查询调用栈没有截断，mixed 的 `RoutePage.lowerBound` 路径明显，public 还出现 `SectionCoverage.groupAt` 与其列表迭代栈。采样权重不是精确分配字节，也不能据一个 recording 宣布性能门通过。此候选只减少 `RoutePage.lowerBound` 对较短 normal 页的二分比较，不改 `shardAtNormal`、normal/shard 数组、ordinal 顺序、coverage、publication、事务/owner/range fence、`groupAt` 或向量数学。

RoutePage 完成现有数组有效性与严格升序验证后，以 widened endpoints 计算 `width = (long) last - (long) first + 1L`。宽度 `<= 64` 时，将每个 normal 的 `(long) normal - first` 位写入一个 `long compactNormalPresence`；宽度 `> 64` 时该字段保持零 sentinel，继续使用原 binary `lowerBound`。compact rank 先处理 `normal <= first` 和 `normal > last`，中间偏移只可能在 1..63；`-1L >>> (64 - offset)` 生成 strictly-before 掩码，`Long.bitCount(presence & before)` 得到相同 lower-bound ordinal。空洞由零位表示；全 int 坐标差值用 long 算，不能溢出或使用 Java shift-count 掩码伪处理 64 位边界。

Candidate-only retained diagnostics 保留原 `routePageNormalPrimitivePayloadBytes`，另报 `routePagePresencePrimitivePayloadBytes`、`compactRoutePages` 与 `wideRoutePages`；每个 live route page 计一个 long payload，宽页零 sentinel 也计入，两个页数之和必须等于 routeBuckets。以上是 primitive field payload 和结构计数，不是对象总 heap 估值。

行为验收由真实 RoutePage 发布与 sample/sampleForStanding 入口比较 scalar oracle：稠密/稀疏 hole、紧凑页宽 64 与宽 65、负法向与 int 极值、lower-bound 前/首项/洞/末项/页后、六面/standing 顺序及 existing page publication fence。沿用已接受的 route page、matched-cell、canonical-face-set 回归，并增加 rank helper 测试；不得改宽阈值或丢失原数组后备路径。验证次序为独立源码 review、API10 focused、候选 typed 9-fixture、完整输入 prerun freeze 与 18-child 三 fixture三 fork窄测/零漂移复核。窄测未达既定性能门仍为 NG，不跑 full-nine 或 release gate。当前此候选刚实现，focused/typed/narrow 均未执行，性能未验收。
